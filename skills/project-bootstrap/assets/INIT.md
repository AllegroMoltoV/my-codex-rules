## 実行手順

最初に `AGENTS.md` のルールを把握してください。その後、要件を読み取り、次の手順を順番に実行してください。

### 1. 作業用ディレクトリの作成

プロジェクトルートに次のディレクトリを作成してください。既存のファイルやディレクトリは上書きしないでください。

- `.appendix`: Git 管理に含めない補足ファイルの保存先
- `.tmp`: コマンド出力などの一時ファイルの保存先
- `.logs`: シェルスクリプトの実行ログの保存先
- `.prompts/PLANS`: 設計と承認に使う計画ファイルの保存先
- `.prompts/DISCUSSIONS`: 計画の懸念事項と選択肢の保存先
- `.prompts/INSPECTIONS`: 検査結果の保存先
- `docs/reports`: 調査レポートの保存先
- `docs/logs`: 再確認が必要な実行ログの保存先

`docs/INDEX.md` がない場合は作成し、文書の保存先を一覧化してください。

### 2. Beads の初期化

`.beads-optout` がある場合は、この手順を省略してください。Beads データベースがない場合は、次のコマンドで個人用の進捗管理を初期化してください。

```powershell
bd init --stealth --skip-agents --non-interactive --init-if-missing
```

グローバル Codex 統合、コミット、`bd dolt push` は実行しないでください。

### 3. 現状の調査

要件に関連する情報を、非破壊操作で可能な限り収集してください。

- ファイル、ディレクトリ構造、Git 履歴の確認
- API 文書、既存設定、依存関係の確認
- 利用可能な接続先がある場合の読み取り操作

調査結果は `docs/reports/` に保存し、`docs/INDEX.md` から参照できるようにしてください。

### 4. 長期タスクの登録

複数セッションへまたがる作業、依存関係、ブロッカー、後続課題だけを Beads へ登録してください。短時間で完了する単発作業は登録しないでください。

`.prompts/PLANS` は設計と承認の記録です。Beads は実行状態と依存関係の正本です。

### 5. 要件の不明点の確認

手順 3 の調査後も不足している情報や曖昧な点だけを確認事項として挙げてください。調査で判明済みの事項は含めないでください。

推奨案を含む複数案を `.prompts/QUESTIONS.md` に保存してください。保存後、私に回答を依頼してください。回答を待ってから次の作業に進んでください。
