# 日本語技術文書

日本語の技術文書を新規作成または改稿するときに、この規則を適用する。チャット、UI、チケット文案などは、利用者が明示した場合を除いて対象にしない。

## 文書の目的を確認する

対象文書と関連資料を通読し、読み手、目的、前提条件、完了後に読み手が取る行動を確認する。既存文書を改稿するときは、事実関係と用語を変えず、根拠のない説明を追加しない。

## 構成を決める

背景や目的など抽象度の高い説明から始め、設計、手順、検証結果など具体的な内容へ進める。序論、本論、結論や、背景、提案、検証、考察など、文書の目的に適した一般的な構成を使う。

手順の前には、その操作が必要な理由や目的を短く説明する。見出しには、環境変数の設定のように内容を具体的に表す名前を付ける。図が文章より関係を明確にする場合は Mermaid を使う。

README には、プロジェクトの目的、背景、内容物、使い方を記載する。初見の読者が作業を開始できる情報をそろえ、末尾に版ごとの更新情報を置く。

## 明瞭な日本語を書く

- 日本語で、技術文書に適したフォーマル寄りの文体を使う。
- 専門用語は、対象読者が理解できない可能性がある場合に意味を補う。
- 衒学的な表現、冗長な受け身、英語の直訳調を避け、平易で短い文にする。
- 一文に複数の主張を詰め込まず、長くなる場合は文を分ける。
- 箇条書きは並列な項目にだけ使い、通常の説明は文として完結させる。
- 助詞を適切に使い、主語と述語の関係を明確にする。
- 整理する、寄せる、効く、包括的に、一気通貫で、ポイントは、要点は、など意味が広い表現を避け、実際の操作や結果を書く。
- 同じ対象には同じ用語を使い、理由なく言い換えない。
- endpoint や agent のように一般的な日本語表現がある語は、エンドポイント、エージェントのように書く。カタカナ語も必要な範囲に限る。

## 表記を統一する

- 半角英数字と全角文字の境界には半角スペースを入れる。ただし、句読点の直後は省略できる。
- 全角文字どうしを空白で分断しない。助詞、活用語尾、謙譲語や丁寧語の接頭辞の前後には空白を入れない。
- 全角かっこと全角コロンは使わない。
- 半角かっこの外側には空白を入れ、内側には入れない。例: `代替現実ゲーム (ARG) は`。
- 半角コロンの直後には空白を入れる。例: `ARG: 代替現実ゲーム`。
- 日本語文章中ではダブルクォーテーションを使わない。コード、設定値、識別子の引用はコード書式を使う。
- ひとつひとつ、一発逆転などの日本語の語を算用数字へ置き換えない。数量や順序のように異なる数へ置き換えられるものは算用数字を使う。
- 4 桁以上の数にはコンマを付ける。

## 仕上げを確認する

書き終えたら、事実と根拠、構成、用語の一貫性、助詞、句読点、境界スペースを読み直す。特に、助詞や活用語尾の直前に不自然な半角スペースがないことを確認する。既存文書の目的や意味を変えた箇所があれば、変更理由を説明できる状態にする。
