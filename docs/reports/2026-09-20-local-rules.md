# PC 固有ルールの導入方式と検証

## 目的

Windows と macOS で、配布リポジトリの標準セットアップから PC 固有ルールを導入・更新できるようにする。利用手順は [README](../../README.md) を参照する。

## 読込みの仕組み

Codex が標準で読むグローバル指示は、Codex ホームの `AGENTS.override.md` または `AGENTS.md` である。同じ階層では空でない最初のファイルが選ばれる。`AGENTS.local.md` は標準の自動検出名ではない。[OpenAI の公式仕様](https://developers.openai.com/ja-JP/docs/agent-configuration/agents-md)

このリポジトリでは、`rules/AGENTS.md` を共通原本、`$CODEX_HOME/AGENTS.local.md` を任意の PC 固有原本とし、標準セットアップが共通ルールの後ろへ PC 固有ルールを追加する。出力は `$CODEX_HOME/AGENTS.md` となる。ローカル原本を空にするか取り除いて再実行すれば、共通ルールだけを配置する。

ローカル原本は利用者が管理する入力であり、セットアップ、更新、取り消しで書き換えない。PowerShell 版の出力ハッシュ、既存バックアップ、ロールバックの管理対象にも加えない。これにより、以前のバックアップを復元しても、ローカル原本を古い内容へ巻き戻さない。

## 修正した問題

- PowerShell 版は共通原本だけをコピーしていたため、ローカル原本が存在しても反映しなかった。
- macOS 版は結合に対応していたが、ローカル原本を外した後に生成済みの出力を管理対象として認識できず、再実行が停止していた。
- README の pull だけで反映される説明は、ローカル原本がある場合の生成済みファイルに当てはまらなかった。両 OS とも、更新後に同じ標準セットアップを再実行する手順へ統一した。

## 検証結果

macOS arm64 上で、シェルと PowerShell 7.6.6 を使って確認した。PowerShell はテスト専用の一時領域へ配置し、通常利用する macOS 版の依存関係には追加していない。

| 検証 | 結果 |
|---|---|
| PowerShell の既存テストと追加テスト | 46 件成功 |
| 両セットアップのローカル原本追加・更新・解除 | 成功 |
| 再実行時の重複防止と原本保持 | 成功 |
| UTF-8 BOM、CRLF、末尾改行なしの入力 | 成功。両実装のルール生成結果がバイト単位で一致 |
| 非空 override による停止と既存の上書き防止 | 成功 |
| PowerShell 版の更新失敗時のロールバックと完全復元 | 成功。ローカル原本を保持 |
| 実際の Beads と Codex を使う隔離統合検証 | 成功。実利用者の設定が変わらないことも確認 |
| macOS の標準セットアップによる実利用環境への反映 | 成功。最新共通原本とローカル原本の結合に一致 |

新しい読取り専用 Codex セッションで、最新の計画管理・反証回数・テスト方針と PC 固有の外部サービス書込み制限を回答できることを確認した。質問文にルール本文を含めず、ツール呼出しもなかったため、起動時に渡された指示からの確認となる。配置時に PC 固有原本、Codex 設定とフックの内容が変わっていないことも確認した。

## 検証範囲

PowerShell 側は macOS 上の実行検証であり、Windows 実機での検証ではない。既存テストの外部コマンド代替を `.cmd` から `.ps1` へ変更し、同じテストを両環境で実行できるようにした。

ファイルの配置確認と、Codex が起動時に指示を受け取ったことの確認は区別する。配置後も以前から続くセッションには古い指示が残り得るため、新しいセッションで確認する。
